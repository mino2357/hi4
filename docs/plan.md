# hi4 企画書（第 0 版）

直列 4 気筒・直噴・ターボ過給のガソリン機関を，吸気口から排気口までの機関システム全体として 1 次元の圧縮性流れ（1D CFD）で解き，吸排気の脈動を見えるようにするシミュレータの企画．設計は `docs/design.md`．

この文書は企画の段階のもので，要件（REQ）にはまだ分けていない．数値のうち，実行して確かめていないものは「推定」と書く．

## 1. 背景と目的

### 1.1 背景

前身の `ice_2026` は，単気筒の 4 ストローク SI 機関を 0 次元（筒内は単一ゾーン，吸排気は容積と集中定数の慣性）で解く．吸気ランナと排気管は，それぞれ 1 つの質量流量を状態に持つ集中定数の振動子（Helmholtz 型）で，圧力波が管の中を有限の速さで伝わること，管端や合流部で反射すること，気筒どうしが干渉することは扱わない．`ice_2026` の要件定義書 1.3 節は「1 次元の圧力波，多気筒」を対象外と明記している．

多気筒の過給機関では，次の現象が性能を決める．どれも圧力波の伝播そのものである．

1. 排気の blowdown の圧力波が，ほかの気筒の排気弁の overlap の時期に届く（排気干渉．4 気筒は点火の間隔が $180^\circ$CA なので特に強い）．
2. 吸気ランナとサージタンクの中の波による慣性過給・共鳴過給と，気筒ごとの体積効率の差．
3. タービンが脈動する流れで駆動されること（pulse turbocharging），twin-scroll による気筒の分離．
4. 直噴と過給を組み合わせたときの scavenging（overlap の間に吸気圧が排気圧を上回り，新気が燃焼室を吹き抜ける）．
5. コンプレッサのサージ，スロットルを閉じたときの管内の圧力波．

### 1.2 目的

1. 直列 4 気筒・直噴・ターボ過給のガソリン機関の，エアクリーナから排気口までを 1 つのネットワークとして解く．管の中は準 1 次元の Euler 方程式（断面積の変化，壁面摩擦，壁面熱伝達，組成の移流を含む）を有限体積法で解く．
2. 吸排気の脈動を，位置と時刻（クランク角）の関数として見えるようにする：管に沿った圧力の $x$–$t$ 線図，任意の位置の圧力・流速・温度の波形，右向きと左向きの波への分解，回転次数の分析．
3. 過給機（コンプレッサ，タービン，ウェイストゲート，インタークーラ）と機関の釣り合い（matching）を，脈動する流れのまま解く．
4. 数値解法を，解析解のある問題で検証する（設計書 10 節）．モデルの式は導出を省かずに文書にする．

### 1.3 目的としないこと

- 実在する特定の機関の再現，実測値への合わせ込み（基準の諸元は，一般的な値から作った架空の機関）．
- 3 次元の流れ（筒内の tumble，噴霧，混合気の分布），燃焼の詳細な化学反応．
- 実時間での計算（3.3 節）．

## 2. 対象とする機関

基準の諸元（既定値．どれも設定で変えられるようにする）．性能の数値は，計算の結果として得るもので，要件にはしない．

| 項目 | 値 |
| :--- | :--- |
| 形式 | 直列 4 気筒，4 ストローク，火花点火，DOHC 4 弁，吸排気とも可変バルブタイミング |
| 内径 $B$ × 行程 $S$ | $84.0\ \text{mm} \times 90.0\ \text{mm}$ |
| 行程容積 | 1 気筒 $V_d = \dfrac{\pi}{4}B^2 S = 498.8\ \text{cm}^3$，合計 $1995\ \text{cm}^3$ |
| 連接棒の長さ $l$ | $145\ \text{mm}$ |
| 圧縮比 $\varepsilon$ | $10.0$ |
| 点火の順序 | 1–3–4–2（間隔 $180^\circ$CA） |
| 燃料の供給 | 筒内直接噴射（吸気行程の噴射が既定） |
| 過給 | 排気タービン式過給機 1 基（single-scroll が既定，twin-scroll は拡張），ウェイストゲート，空冷インタークーラ |
| 排気の後処理 | 三元触媒（当面は流れの抵抗と熱容量としてだけ扱う），消音器 |

## 3. 範囲

### 3.1 モデルに含めるもの

| 部位 | 扱い |
| :--- | :--- |
| 管（吸気管，インタークーラ，ランナ，ポート，排気マニホールド，排気管，触媒，消音器の内部の管） | 準 1 次元の Euler 方程式（有限体積法） |
| 容積（エアクリーナの箱，サージタンク，合流部，タービンの入口と出口，消音器の室） | 0 次元（質量，エネルギー，組成の保存） |
| シリンダ（4 本） | 0 次元（`ice_2026` の筒内モデルを引き継ぐ．ノックの指標のために未燃部の温度を加える） |
| 弁，スロットル，ウェイストゲート | 準定常の圧縮性オリフィス．管端では特性曲線と連立して解く |
| コンプレッサ，タービン | 準定常の特性（map）と，過給機の軸の回転の運動方程式 |
| 回転系 | クランク軸の運動方程式，摩擦，動力計 |
| 制御 | スロットル，過給圧（ウェイストゲート），空燃比，点火時期，バルブタイミング |

### 3.2 当面は含めないもの（拡張の候補）

触媒の反応と昇温，燃料の壁面付着，EGR（外部），可変容量タービン，電動過給，気筒休止，エンジン音の合成，車両（シャシーダイナモメーター）．1 次元の解は管端の圧力と流速の波形を直接与えるので，エンジン音は後で自然に加えられる．

### 3.3 計算の速さについて（推定）

管の全長を約 $7.5\ \text{m}$，格子の幅を $\Delta x = 10\ \text{mm}$ とすると，セルは約 $750$ 個．排気の音速を $a \approx 650\ \text{m/s}$（$\gamma = 1.3$，$R = 287\ \text{J/(kg·K)}$，$T = 1150\ \text{K}$ で $a = \sqrt{\gamma R T} \approx 655\ \text{m/s}$），流速を含めた最大の波の速さを約 $1200\ \text{m/s}$，CFL 数を $0.5$ とすると，時間の刻みは

```math
\Delta t = 0.5 \times \frac{0.010\ \text{m}}{1200\ \text{m/s}} \approx 4.2\ \mu\text{s}
```

$1000\ \text{rpm}$ の 1 サイクル（$120\ \text{ms}$）は約 $2.9 \times 10^4$ ステップ，流束の計算は 1 段につき約 $2.2 \times 10^7$ 回．流束 1 回を $50$〜$200\ \text{ns}$ と見ると，1 サイクルの計算に $1$〜$13\ \text{s}$（3 段の Runge–Kutta なら 3 倍）かかり，実時間の $10$〜$100$ 倍遅い．これは推定で，実装してから測る．

したがって，実時間の再生は目的にしない．脈動は，クランク角を軸にしたスローモーションで見るのが元々適している．回転数と負荷の格子点を回る計算（性能曲線，マップ）は，点ごとに独立なのでスレッドで並列にする．

## 4. 成果物

1. **計算の核**：ネットワーク（管，容積，シリンダ，接続の要素）を解くライブラリ．画面に依存しない．
2. **コマンドラインの道具**：設定のファイルを読み，運転点または回転数の掃引を計算して，波形と性能の指標を書き出す．検証問題もここから実行する．
3. **表示**：系統図の上に圧力・流速・温度・既燃ガスの割合を色で示すアニメーション，$x$–$t$ 線図，プローブの波形，気筒ごとの指標，過給機の map の上の作動点の軌跡．
4. **文書**：要件定義書，仕様書（式の導出を含む），検証の記録．`ice_2026` と同じ形（REQ／SPEC／TEST を同じ番号で対応させる）にする．

## 5. 実装の形（推奨と，利用者の判断が要る点）

推奨：**計算の核を Rust で書き，同じコードをネイティブ（コマンドライン，並列の掃引）と WebAssembly（ブラウザの表示）の両方に使う**．

| 案 | 長所 | 短所 |
| :--- | :--- | :--- |
| A. Rust の核 + CLI + WASM の表示（推奨） | 速い．検証と掃引をネイティブで回せる．表示は単一 HTML にでき，スマートフォンでも動く．SIMD とスレッドを使える | ビルドの道具が増える（cargo，wasm の生成）．`ice_2026` の検証の基盤（Playwright のアプリ内テスト）はそのままは使えない |
| B. `ice_2026` と同じ単一 HTML の JavaScript | 道具と文書の仕組みをそのまま使える．配布が簡単 | 3.3 節の計算量では遅い．並列の掃引が Web Worker に限られる |
| C. C++ の核 + 別の表示 | 速い．既存の資産を使いやすい | ブラウザの表示との共用が A より手間 |

1 次元でセルが $10^3$ 個の規模なので，GPU（CUDA）は要らない．

## 6. 進め方（段階）

各段階の終わりに，その段階の検証（設計書 10 節）を PASS させてから次へ進む．

| 段階 | 内容 | 終わりの判定（例） |
| :--- | :--- | :--- |
| 0 | 企画と基本設計（この文書と `design.md`），利用者の確認，要件（REQ）への分割 | 利用者の承認 |
| 1 | 1 次元のソルバ（単一の管）：MUSCL，HLLC，熱物性，断面積の変化，摩擦，熱伝達 | 衝撃波管，収束の次数，静止の保持，等エントロピーのノズル，Fanno，Rayleigh |
| 2 | 接続：容積，管端のオリフィス，合流部．保存の点検 | 管の共鳴の周波数，Helmholtz 共鳴，オリフィスの定常流量，閉じた系の質量とエネルギーの保存 |
| 3 | シリンダ 1 本と吸排気の管（motoring → 燃焼）．最初の脈動の表示 | 弁が閉じた区間の断熱圧縮，1 サイクルの収支，格子の収束 |
| 4 | 自然吸気の 4 気筒：マニホールド，点火の順序，$x$–$t$ 線図，気筒ごとの体積効率 | 周期定常への収束，体積効率の回転数に対する山と，ランナの長さへの依存 |
| 5 | 過給：コンプレッサ，タービン，軸，ウェイストゲート，インタークーラ，過給圧の制御 | 定常での仕事の釣り合い，map の上の作動点，過給圧の制御の収束 |
| 6 | 直噴，ノックの指標，バルブタイミングと scavenging，性能曲線とマップ | 全負荷の性能曲線，scavenging の質量の収支 |
| 7 | 拡張：twin-scroll，合流部の圧力損失のモデル，過渡（ターボラグ），触媒の熱と反応，エンジン音 | 項目ごとに決める |

## 7. 危険と対策

| 危険 | 対策 |
| :--- | :--- |
| 管端と弁の境界条件が不安定になる（開き始め，閉じる直前，逆流，チョーク） | 境界の問題を 1 つの未知数の方程式に落として解く（設計書 5.2 節）．閉じた弁と完全に開いた端の極限に一致することを検査する |
| 小さい容積やごく短い管が時間の刻みを支配する | 容積の下限と，短い管を容積に置き換える規則を設ける（設計書 4.3 節） |
| 過給機の map が手に入らない | 公開されている式による map（設計書 7 節）を使い，寸法と係数で形を決める．実在の map の再現は目的にしない |
| 過給機の軸の慣性のため，周期定常までに数百サイクルかかる | 定常の運転点を求めるときは，軸の慣性を小さくして収束を早める（定常解は慣性によらない） |
| コンプレッサの特性の逆算が一意でない（サージの近く） | コンプレッサを通る流量を状態量に持つ（Greitzer 型．設計書 7.1 節） |
| モデルが大きくなり，検証が追いつかない | 段階ごとに解析解のある検査を先に作る．保存量の収支を常時点検する |

## 8. 利用者の判断が要る点（未決）

1. 実装の形（5 節の A，B，C）．
2. 基準の機関の諸元（2 節）でよいか．特定の機関に近づけたい場合はその諸元．
3. 過給機：single-scroll を既定とし twin-scroll を拡張に回す順でよいか．
4. 文書と検証の進め方を `ice_2026` の CLAUDE.md と同じ規則（要件が先，テストを先に，段階の検証）にするか．
5. `ice_2026` のコード（熱物性，化学平衡，筒内モデル）を移植するか，書き直すか．
6. 表示の主な対象（スマートフォンの縦持ちか，PC の広い画面か）．$x$–$t$ 線図と系統図は広い画面が向く．
