# hi4 企画書（第 0 版・改 1）

直列 4 気筒・直噴・ターボ過給のガソリン機関を，吸気口から排気口までの機関システム全体として 1 次元の圧縮性流れ（1D CFD）で解き，吸排気の脈動を見えるようにするシミュレータの企画．モデルの設計は `docs/design.md`．

進め方，成果物の形，文書の体系は，前身の `ice_2026`（単気筒・0 次元）に合わせる（2 節）．**どの現象まで扱うかは利用者が決める**．この文書は現象の候補を一覧にするだけで（3 節），採否は決めていない．

この文書は企画の段階のもので，要件（REQ）にはまだ分けていない．実行して確かめていない数値は「推定」と書く．

## 1. 背景と目的

### 1.1 背景

`ice_2026` は，吸気ランナと排気管を，それぞれ 1 つの質量流量を状態に持つ集中定数の振動子（REQ-25，REQ-27）で表す．圧力波が管の中を有限の速さで伝わること，管端や合流部で反射すること，気筒どうしが干渉することは扱わず，要件定義書 1.3 節で「1 次元の圧力波，多気筒」を対象外としている．hi4 はこの 2 つを対象にする．

### 1.2 目的（利用者の指示）

1. 対象は，直列 4 気筒・直噴・ターボ過給のガソリン機関．
2. 機関システムの全体を，1 次元の CFD で作る．
3. 吸排気の脈動を見えるようにする．

`ice_2026` の目的（1.1 節）にならい，利用者が，設定を変えたときの脈動と性能の変化を，保存則が閉じた計算の結果として確かめられることを求める．

## 4. 計算の速さ（推定．未決）

管の全長を約 $7.5\ \text{m}$，格子の幅を $\Delta x = 10\ \text{mm}$ とすると，セルは約 $750$ 個．排気の音速を $a \approx 650\ \text{m/s}$（$\gamma = 1.3$，$R = 287\ \text{J/(kg·K)}$，$T = 1150\ \text{K}$ で $a = \sqrt{\gamma R T} \approx 655\ \text{m/s}$），流速を含めた最大の波の速さを約 $1200\ \text{m/s}$，CFL 数を $0.5$ とすると，時間の刻みは

```math
\Delta t = 0.5 \times \frac{0.010\ \text{m}}{1200\ \text{m/s}} \approx 4.2\ \mu\text{s}
```

$1000\ \text{rpm}$ の 1 サイクル（$120\ \text{ms}$）は約 $2.9 \times 10^4$ ステップ，流束の計算は 1 段につき約 $2.2 \times 10^7$ 回．流束 1 回を $50$〜$200\ \text{ns}$ と見ると，1 サイクルに $1$〜$13\ \text{s}$（3 段の Runge–Kutta なら 3 倍）で，実時間の $10$〜$100$ 倍遅い．スマートフォンの JavaScript ではさらに遅い可能性がある．どれも推定で，測っていない．

これに対する案（利用者の判断が要る）：

1. 実時間を求めない．計算はクランク角で進め，表示はスローモーションにする（脈動を見る用途には元々向く）．
2. 格子を粗くする，時間積分の段を減らす（精度との兼ね合いを測って決める）．
3. 単一 HTML のまま，計算を Web Worker に分ける，または WebAssembly にする（C-1 の「単一の HTML」は保てるが，`ice_2026` の道具と検証の仕組みに手が入る）．

要件を決める前に，主対象の環境で管 1 本の計算の速さを測る小さな道具を作って数を出すことを勧める（`ice_2026` の `docs/report_*.md` と同じ扱い）．

## 6. 進め方

1. 利用者が 3 節の採否と，4 節，5 節を決める．
