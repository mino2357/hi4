# Q-17：式の正本を Rust の型付きの関数にするか，単位と形式的な検査をどこまで行うか

## 決めること

実装を始めるときに，式の正本を，文書（`docs/model/eq-*.md`）から Rust の型付きの関数（署名，doc コメントの数式，本体）に移すか．単位の検査と，より形式的な検査を，どの手段で行うか．

## 判断の材料

- 利用者（2026-11-28）：「単位による検査も検討」「実装言語も型で分かるような言語を使う」「もっと形式的に検査できないかは引き続き検討」「もっと文字数削れるはず」．Rust で式を書く案に対しては「実装はまだ先の話なので，こころに留めるだけで良い．まだコードは書かない」．
- Rust の関数の署名にすると，定める量（戻り値），使う量（引数），単位（型）が 1 か所になり，量の表と式の欄が要らなくなる．無い量を使う，次元が合わない，同じ量を 2 か所で定義する，切替の片方に式が欠ける，はコンパイルが通らない．「式との一致」の検査は要らなくなる（式そのものがコード）．
- 残る弱点：doc コメントの数式と本体の食い違い，連立して解く組（陰に決まる式）の検査，保存の対（流れの出る側と入る側）．
- いまの文書の形では，単位は量の表に書いてあるだけで，式の両辺の次元は調べていない（式が TeX で，機械が読めないため）．

## 選択肢

(a) 実装を始めるときに，式の正本を Rust の関数に移す．

(b) 文書の式を正本のままにし，実装はそれを写す．

決めるのは，実装を始めるとき．
