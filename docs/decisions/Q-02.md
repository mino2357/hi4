# Q-02：計算の速さの扱い

## 決めること

`ice_2026` の目的にある「実時間に可視化」を，hi4 でどう扱うか．

## 判断の材料

管の全長を約 $7.5\ \text{m}$，格子の幅を $\Delta x = 10\ \text{mm}$ とすると，セルは約 $750$ 個．排気の音速を $a \approx 650\ \text{m/s}$（$\gamma = 1.3$，$R = 287\ \text{J/(kg·K)}$，$T = 1150\ \text{K}$ で $a = \sqrt{\gamma R T} \approx 655\ \text{m/s}$），流速を含めた最大の波の速さを約 $1200\ \text{m/s}$，CFL 数を $0.5$ とすると，時間の刻みは

```math
\Delta t = 0.5 \times \frac{0.010\ \text{m}}{1200\ \text{m/s}} \approx 4.2\ \mu\text{s}
```

$1000\ \text{rpm}$ の 1 サイクル（$120\ \text{ms}$）は約 $2.9 \times 10^4$ ステップ，流束の計算は 1 段につき約 $2.2 \times 10^7$ 回．流束 1 回を $50$〜$200\ \text{ns}$ と見ると，1 サイクルに $1$〜$13\ \text{s}$（3 段の Runge–Kutta なら 3 倍）で，実時間の $10$〜$100$ 倍遅い．スマートフォンの JavaScript ではさらに遅い可能性がある．どれも推定で，測っていない．

要件を決める前に，主対象の環境で管 1 本の計算の速さを測る小さな道具を作って数を出すことを勧める（`ice_2026` の `docs/report_*.md` と同じ扱い．道具を作るのは利用者の指示の後）．

## 選択肢

(a) 実時間を求めない．計算はクランク角で進め，表示はスローモーションにする（脈動を見る用途には元々向く）．

(b) 格子を粗くする，時間積分の段を減らす（精度との兼ね合いを測って決める）．

(c) 単一 HTML のまま，計算を Web Worker に分ける，または WebAssembly にする（C-1 の「単一の HTML」は保てるが，`ice_2026` の道具と検証の仕組みに手が入る）．

## 決定

(a) 実時間を求めない．計算はクランク角で進め，表示はスローモーションにする（利用者）．
